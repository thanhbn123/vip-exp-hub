### 2.2 `app/migrate.py` — `nang_len_v10(kn)`

Đặt sau `nang_len_v9`, **giữ nguyên `nang_len_v9`**. Đúng khuôn `nang_len_v9`/`nang_len_v8`:
**chạy hằng DDL của chính module**, không chép DDL.

```python
def nang_len_v10(kn):
    buoc = []
    import truy_van                                   # nạp muộn, như v8/v9

    truoc = {r[0] for r in kn.execute(
        "SELECT name FROM sqlite_master WHERE type IN ('table','index')")}
    chay_ddl_trong_giao_dich(kn, truy_van.DDL_G12Q)   # ← hằng của module, KHÔNG chép
    sau = {r[0] for r in kn.execute(
        "SELECT name FROM sqlite_master WHERE type IN ('table','index')")}
    them = sorted(sau - truoc)
    buoc.append("G19/C6 chỉ mục lớp truy vấn G12 (`truy_van.DDL_G12Q`): "
                f"+{len(them)} đối tượng" + (f" ({', '.join(them)})" if them else " (đã có sẵn)"))
    return buoc
```

Thang nâng cấp trong `chay()` thêm đúng một nhánh:

```python
        if pb < 9:
            buoc += nang_len_v9(kn)
        if pb < 10:
            buoc += nang_len_v10(kn)
```

Vì sao dùng `chay_ddl_trong_giao_dich` chứ không `executescript`: hàm này tách câu bằng
`sqlite3.complete_statement` và **không tự COMMIT** giao dịch đang mở — migration vẫn nguyên tử
(đã đo ở `nang_len_v8`/`nang_len_v9`). `DDL_G12Q` chỉ có `CREATE INDEX IF NOT EXISTS`, nên bước
v10 chạy lại vô hại.

## 7. Việc còn lại / ghi nhận ngoài phạm vi

1. **Chạy migration trên kho thật**: chưa làm và không được làm trong task này. Khi triển khai,
   `migrate.py` sẽ tự `sao_luu()` (bản ghi + `.sha256` trong `sao-luu/`) trước khi áp 9 chỉ mục.
   Server hiện **từ chối khởi động** khi CSDL ở v9 và mã cần v10 — đúng thiết kế, phải chạy
   migration trước.
2. **Rollback**: bản vá chỉ THÊM 9 chỉ mục + một dòng `schema_version=10`. Khôi phục bằng bản
   `sao-luu/hub-truoc-migrate-*.db` do chính lượt migrate tạo; vì đó là tụt schema (10 → 9),
   `khoi_phuc()` fail-closed sẽ đòi cờ `--toi-da-biet-chua-kiem-duoc` — phải xác nhận có chủ ý.
3. **Ba bộ thử sẵn có đang hỏng/không ổn định, KHÔNG do v10** (đã đối chứng bằng bản sao cây
   TRƯỚC bản vá, chạy cùng lệnh):

     chưa khai kho); chạy kèm biến này thì **40/40 ĐẠT** trên schema v10.

     trường này (`disk I/O error` / `Errno 2` khi cùng tạo CSDL WAL mới). Bản sao **trước bản
     vá** cũng hỏng 2/3 lượt với cùng lỗi; không phải do v10.
   - `app/thu/thu_g01_g02.py::test_014` (nhánh rollback): bản sao lưu fixture v1 không có bảng
